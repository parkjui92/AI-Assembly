쓰는 법

  • API — 기관이 자료를 JSON·XML로 내어 주는 창구 — 명세서를 Claude Code에 주고 "이 API로 ~을 조회하는 스크립트를 짜줘"라고 시킴
  • MCP — 창구를 대화 안에 상시 연결하는 표준 규격 — 저장소 주소를 주고 "README대로 설치해줘"라고 말함 · 인증키는 사람이 직접 넣음
  • 고르는 순서 — 만들어진 MCP가 있으면 설치, Open API만 있으면 스크립트, 웹 화면뿐이면 내려받은 hwp·pdf를 kordoc으로 읽힘
  • 카드의 파란 상자 — 그대로 복사해 Claude Code 입력창에 붙이는 말 — 법률명·검색어 자리만 내 것으로 바꿈
  • 확인 표시 — 「검증」은 공식 페이지·README 원문을 직접 대조한 것, 「색인확인」은 접속이 막혀 주소·명칭만 확인한 것, 「2차」는 이번 조사 메모 등 2차 자료로 확인한 것
  • 직접 API를 익힐 필요는 없음 — 인증키 발급과 결과 대조는 사람이 맡음

Claude Code에 MCP 붙이기

claude mcp add [옵션] <이름> -- <실행 명령> [인자...]   # 내 컴퓨터에서 실행하는 서버(stdio)
claude mcp add --transport http <이름> <URL>            # 원격 서버(HTTP)
claude mcp add --env KEY=값 --transport stdio <이름> -- <실행 명령>   # 환경변수 넘기기
claude mcp list · claude mcp get <이름> · claude mcp remove <이름>   # 관리 · 대화 중에는 /mcp
  • 적용 범위(--scope) — local(기본, 지금 프로젝트에서 나만) · user(내 모든 프로젝트) · project(폴더의 .mcp.json에 저장돼 폴더를 받은 사람과 공유)
  • 인증키 보관 — 키는 셸 환경변수로(예: ~/.zshrc에 export LAW_OC=본인 발급 값), .mcp.json에는 ${LAW_OC}처럼 변수 이름만 · .env 파일은 .gitignore에 등록
  • 승인 절차 — 남이 준 폴더의 .mcp.json 서버는 사용 전에 승인을 물음 · 모르는 서버는 승인하지 않음
  • 문법 출처: code.claude.com/docs/en/mcp

먼저 지킬 것

  • 소속 기관의 생성형 AI 이용 지침이 이 자료보다 우선함
  • 넣지 않는 것 — 비공개 문서, 공개 동의 전의 비용추계 회답, 공개되지 않은 부처 제출자료, 검토 중인 내부 의견, 개인정보가 담긴 자료 — 공개된 의안·법령·회의록·통계로 시작함
  • 외부 서버를 거치는 도구를 구분함 — korean-law-mcp 플러그인·웹 커넥터는 제작자 공개 서버를 거쳐 조회함 — 검토 중인 문안을 넣는 조회는 내 컴퓨터 설치 방식으로
  • 인증키를 채팅 창에 붙이지 않음 — 대화 기록에 남음 — "키는 환경변수 LAW_OC에서 읽어"처럼 변수 이름만 알려 줌 · 주소(URL)에 키를 넣는 방식은 접속 기록에 평문으로 남을 수 있어 헤더·환경변수 방식을 씀
  • 유출 의심 시 재발급함 — 법제처 마이페이지 'API인증키관리', 열린국회정보 '인증키 발급내역'
  • MCP 설치는 남이 만든 코드를 내 컴퓨터에서 실행하는 일 — 연결 전 서버를 신뢰할 수 있는지 확인(Claude Code 공식 문서 경고), 공식 저장소의 설치 명령만 복사함 · 외부 자료를 읽힌 뒤 Claude가 제안하는 명령·파일 수정은 승인 전에 읽어 봄(프롬프트 인젝션)
  • 호출 한도를 지시에 넣음 — "100건씩 끊어서, 한 번에 1,000건까지만"처럼 상한을 정해 시킴
