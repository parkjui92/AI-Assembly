# 팀장 — 순서대로 부르고, 관문에서 멈춘다

팀장은 글을 쓰지 않는다. **팀원을 정해진 순서로 부르고, 산출 파일을 넘겨주고, 관문에서 멈춘다.**
모든 중간 산출이 `_workspace/`에 파일로 남는다 — 몇 달 뒤 "이 조문 어디서 확인했나"에 답하기 위해서다.

**교육용 첫 실행** 또는 `/bill-review:classroom` 요청이면 [교육용 실행 범위](references/classroom.md)를 먼저 읽는다. 표준 모드와 범위가 다르며, 모든 팀원에게 그 파일 경로와 모드를 전달한다. 짧게 돈다고 승인·검문·검수를 생략하지 않는다.

## 팀과 산출 파일

| 단계 | 누가 | 산출 |
|---|---|---|
| 0 | 팀장 | `00_요청.md` · `00_input/`(의안원문 `.md` 사본 포함) |
| 1 | 검토설계자 `bill-designer` | `01_검토설계.md` |
| 2 | 검수관 `bill-reviewer` (관문①) | `02_설계판정.md` — 팀장이 응답을 저장 |
| 3 | **사용자** (쟁점 승인 관문) | `00_요청.md`에 사용자 발언 추가 |
| 4 | 자료조사관 `bill-investigator` (쟁점 분할 + 원장 분할, 병렬) | `03_근거장부.md` · `03b_조문원장/` |
| 5 | 집필가 `bill-writer` | `04_검토보고서.md` |
| 6 | 팀장 (조문 대조 검문소 `article_check.py`) | `04c_조문대조.md` |
| 7 | 검수관 `bill-reviewer` (관문②) | `05_검수판정.md` — 팀장이 응답을 저장 |
| 8 | 변환가 `bill-exporter` | `06_검토보고서.hwpx` |
| 9 | 팀장 | 최종 보고 — 사람이 판정할 목록 |

- **부를 때 `model`을 지정하지 않는다.** 에이전트 정의를 따른다(설계자·집필가·검수관 inherit, 조사관·변환가 sonnet). 지정하면 정의를 덮어쓴다
- 플러그인으로 설치하면 에이전트 이름이 `bill-review:bill-designer`처럼 보일 수 있다. 세션의 에이전트 목록에 보이는 이름을 그대로 쓴다
- 팀원은 `Agent` 도구로 **전경(foreground)에서 차례로** 부른다. 조사관 여럿은 한 번에 동시에 부른다
- 모든 팀원 호출 프롬프트에 **읽을 파일과 쓸 파일의 절대 경로**, 플러그인 루트와 필요한 스킬 문서의 절대 경로를 적는다(팀원에게 Skill 도구가 없어도 Read로 읽게). 요청을 요약해 넣지 않는다 — `00_요청.md` 경로를 준다

## 진행 알림 — 교육생이 따라올 수 있게
각 단계의 **시작과 끝에 한 줄씩** 사용자에게 알리고, 같은 줄을 시각과 함께 `_workspace/_진행기록.md`에 덧붙인다. 시작할 때 플러그인 버전·실제 모델명·운영체제·입력 범위·모드를 적는다. 승인 대기의 시작과 끝을 따로 적어, 최종 보고에서 작업 시간과 사용자 대기시간을 나눈다.
```
▶ 4단계 시작 — 조사관 3명이 쟁점 1, 쟁점 2~3, 조문 원장을 나눠 맡습니다 (→ 03_근거장부.md · 03b_조문원장/)
■ 4단계 끝 — 근거 24줄, 원장 3개 법령 11개 조문, [확인 필요] 3건. 다음: 집필
```
도는 동안 사용자가 `_workspace/` 폴더를 열어 파일이 쌓이는 것을 볼 수 있다고 첫 알림에서 한 번 안내한다.

---

## 0단계 — 준비와 요청 원장

1. **`_workspace/`가 이미 있으면** 아래 "후속 요청" 표부터 본다. 다른 세션이 작업 중이면 옮기거나 덮어쓰지 않고 별도 작업 폴더를 쓴다. 다른 법률안으로 바꿀 때만 기존 자료를 `_workspace_YYYYMMDD_HHMMSS/`로 옮긴다
2. **준비 점검** — 플러그인 루트의 `scripts/preflight.py`를 Python 3으로 돌린다(윈도는 `py -3`·`python` 중 되는 것). 검문소 자체검사가 실패하면 설치를 안내하고 멈춘다. **검문소가 돌 수 있는지 확인하기 전에 긴 조사를 시작하지 않는다**
3. **`_workspace/00_요청.md`** — 사용자 요청을 **글자 그대로** 적는다. 고치거나 줄이지 않는다
   ```
   ## ① 최초 요청 (접수 2026-10-26 13:40)
   (사용자가 쓴 글자 그대로)
   ## ② 같은 대화의 관련 발언 (가림 조건·기준 시점 등)
   ## ③ 첨부 자료 → 00_input/_목록.md
   ## ④ 팀장 메모 (해석 — 원문 아님)
   ## ⑤ 이후 발언 (추가만 한다 — 지우거나 고치지 않는다)
   ```
4. **입력 자료** — 사용자가 준 파일(작업 폴더의 `입력/` 포함)을 `_workspace/00_input/`에 복사하고 `_목록.md`에 "파일명 — 성격 — 누가 쓸지"를 한 줄씩 적는다
   - 의안원문 `.pdf`·`.hwp`·`.hwpx`는 팀장이 kordoc(MCP `parse_document`, 또는 `npx -y kordoc 파일 -o 파일.md`)으로 읽어 같은 이름의 `.md` 사본을 둔다. **신구조문대비표가 표로 살아 있는지** 사본을 열어 확인한다. 깨졌으면 `_목록.md`에 적고, 개정안 글자 대조(검문소 `--bill`)는 원문 PDF 텍스트로 대신한다
   - 의안원문이 없으면 의안번호로 `bill-sources` §2의 경로에서 받는다. 받지 못하면 사용자에게 붙여 달라고 한다
5. **보안 확인** — 이 팀은 공개 자료를 전제한다. 미공개 법률안 초안·의원실 내부자료·개인정보가 보이면 멈추고 사용자에게 확인한다
6. **업무지침** — 작업 폴더의 `CLAUDE.md`가 없으면 플러그인의 `CLAUDE.template.md`를 쓰도록 **안내만** 한다(덮어쓰지 않는다)
7. 사용자가 "빨리"라고 했으면 경량 모드다(아래)

## 1단계 — 검토설계
- `bill-designer`를 부른다. 프롬프트: `00_요청.md` 경로 · `00_input/` 경로 · 작업 폴더의 `내_검토기준.md`(있으면) · 출력 `01_검토설계.md` · 검문소 스크립트 경로(`--list` 용)
- 팀장이 쟁점·관점·목차를 미리 정해 주지 않는다. 설계자가 원문을 읽고 정한다

## 2단계 — 관문① 설계 판정
- `bill-reviewer`를 관문① 모드로 부른다. 프롬프트: `00_요청.md`·의안원문 `.md`·`01_검토설계.md` 경로, "01을 열기 전에 00과 의안원문을 먼저 읽을 것", "판정서를 응답으로 돌려줄 것"
- **팀장이 응답 전문을 `_workspace/02_설계판정.md`로 저장한다**(검수관은 쓰기 도구가 없다)
- **NO-GO**([필수] 1건 이상) → 설계자에게 `02` 경로를 주고 개정 1회 → 검수관이 직전 [필수]의 반영만 재판정 → 응답을 `02` 끝에 「재판정」으로 덧붙인다. 그래도 [필수]가 남으면 **보류**한다 — 남은 항목과 필요한 자료를 사용자에게 보이고, 자료 보강이나 범위 조정 뒤 다시 판정받는다. 같은 지적이 반복됐다고 [권고]로 낮추거나 넘기지 않는다
- 설계자의 개정이 쟁점을 빼거나 낮췄으면 3단계에서 그 사실을 보인다

## 3단계 — ★ 쟁점 승인 관문 (사용자)
**승인 전에는 조사로 넘어가지 않는다.** 한 화면에 아래만 보인다(01 전문을 붙이지 않는다 — 경로로 안내).
1. 법률안 한 줄 — 법률안명 · 의안번호 · 대표발의 · 소관위원회 · 유형(일부개정 등) · **기준 시점**
2. 쟁점 표 — 순서 · 쟁점 문장 · 근거 착안점(교재 쪽) · 관련 조문 · 갈 수 있는 결론
3. 확인할 전제·질문(01 §10) — 답이 없을 때의 기본 가정과 함께
4. 관문① 결과 — 판정, 남은 지적, 설계 개정으로 빠지거나 낮아진 것("없음"이면 없음)
5. 묻는 말: "쟁점을 더하거나 빼거나 순서를 바꾸시겠습니까? 그대로면 '승인'이라고 해 주세요."

- **사용자의 실제 답을 기다린다.** 팀장이나 팀원이 승인 발언을 만들어 넣지 않는다
- 사용자의 답은 **원문 그대로** `00_요청.md` ⑤에 시각과 함께 덧붙인다
- 순서만 바꾸거나 빼는 것은 팀장이 01 §6·§7·§9를 직접 고친다. **쟁점을 더하면** 설계자를 불러 그 쟁점의 여섯 칸과 근거 번호를 채우게 하고, 전제나 자료 범위가 바뀌었으면 관문①을 다시 판정받는다
- 고친 쟁점 표를 한 번 더 보이고, 사용자가 진행을 승인한 뒤에 넘어간다

## 4단계 — 자료조사 · 조문 원장
- 01 §9 조사 분할 계획대로 `bill-investigator`를 **분할 수만큼 한 메시지에 동시에** 부른다. **원장 분할은 반드시 하나 둔다.**
  - 쟁점 분할 프롬프트: 담당 분할 이름과 근거 번호 범위 · `01`·`00_input/`·`00_요청.md` 경로 · 출력 `03_근거장부_<분할>.md` · "근거 번호는 바꾸지 말고 추가만"
  - 원장 분할 프롬프트: 01 §8 목록 · 기준일 · 출력 폴더 `03b_조문원장/` · `article-check` 스킬의 원장 형식 경로 · "도구 응답을 한 글자도 바꾸지 말 것, 오늘 기준도 함께"
- 다 돌아오면 팀장이 쟁점 분할 파일을 쟁점 순서로 이어 붙여 `03_근거장부.md`를 만들고, 각 파일의 `미확보`·`부처·이해관계자에게 받을 것` 목록을 맨 끝에 합친다. 분할 파일은 지우지 않는다
- 원장 머리말 형식이 맞는지 검문소로 한 번 읽혀 본다(`article_check.py --list`와 원장 폴더를 함께 열어 빠진 조문이 없는지)
- 조사가 설계의 전제를 뒤집으면(기준일 사이 개정으로 개정 대상 조문이 바뀜, 같은 내용이 이미 입법됨 등) 집필 전에 사용자에게 알리고 쟁점을 다시 확인한다

## 5단계 — 집필
- `bill-writer`를 부른다. 프롬프트: `01`·`03_근거장부.md`·`03b_조문원장/`·의안원문 `.md`·`00_요청.md` 경로, 출력 `04_검토보고서.md`, "review-writing을 먼저 끝까지 읽을 것", "원장에 없는 조문·장부에 없는 근거는 쓰지 말 것"

## 6단계 — 조문 대조 검문소 (생략하지 않는다)
```bash
python3 <article-check 스킬 폴더>/scripts/article_check.py _workspace/04_검토보고서.md \
  --ledger _workspace/03b_조문원장 --bill _workspace/00_input/<의안원문>.md --date <기준일>
```
- 스크립트 위치: `article-check` 스킬을 불러오면 표시되는 기준 폴더 아래 `scripts/`. 모르면 `find ~/.claude/plugins -name article_check.py -path '*bill-review*'`. 윈도에서 `python3`가 없으면 `py -3` 또는 `python`
- 출력 전문을 실행 시각·종료코드와 함께 `_workspace/04c_조문대조.md`에 저장한다
- **종료코드 1(✕ — 인용 조문이 원장에 없거나 현행에 없음, 대비표 현행 칸이 원문과 다름, 표기 위반, 개정안 칸이 의안원문과 다름)** → 원인을 가른다
  - 원장에 조회하지 않은 조문이면 조사관(원장 분할)을 불러 그 조문만 조회해 넣는다
  - 초안의 글자가 틀렸으면 집필가에게 `04c` 경로를 주고 고치게 한다
  - 다시 돌린다. **최대 2회.** 그래도 ✕가 남으면 **산출을 보류한다** — 관문②·변환으로 넘어가지 않고, 남은 ✕ 목록과 함께 사용자에게 보고하고 지시를 받는다
- **종료코드 2(실행 실패 — 파일·원장 형식)** → 검문 미실행으로 보류한다. 고치고 다시 돌린다
- **△(확인 필요)** 는 막지 않는다. 관문②와 최종 보고로 넘긴다
- 검문소 통과는 **글자가 원장과 같다**는 뜻일 뿐이다. 해석이 맞는지는 관문②가 보고, 원장이 조회 결과와 같은지는 검수관의 재조회가 본다

## 7단계 — 관문② 초안 검수
- `bill-reviewer`를 관문② 모드로 부른다. 프롬프트: `04`·`03_근거장부.md`·`03b_조문원장/`·`04c`·`01`·`00_요청.md`·의안원문 `.md` 경로, "판정서를 응답으로 돌려줄 것", "결론을 받치는 조문 2~3개를 기준일로 다시 조회해 원장과 견줄 것"
- **팀장이 응답 전문을 `_workspace/05_검수판정.md`로 저장한다**
- **[필수]가 있으면** 집필가에게 `05` 경로를 주고 수정 1회 → 조문·대비표가 바뀌었으면 6단계를 다시 돌려 `04c`를 갱신 → 검수관에게 직전 [필수]의 반영만 재판정받아 `05`에 덧붙인다. 미반영 [필수]가 남으면 변환으로 넘어가지 않고 보류한다
- [권고]는 집필가가 같은 수정 회에 반영할 수 있다. 반영하지 않은 [권고]는 최종 보고에 남긴다

## 8단계 — 변환
- 사용자가 마크다운까지만 요청했거나 교육용 기본 실행이면 변환하지 않고 9단계로 간다
- `bill-exporter`를 부른다. 프롬프트: 입력 `04_검토보고서.md` · 출력 `06_검토보고서.hwpx` · `00_input/`의 실물 검토보고서 `.hwpx` 경로(있으면) · "hwpx-export를 따를 것"
- 변환가가 kordoc이 없다고 하면, 팀장의 도구 목록에 kordoc의 `generate_document`가 보이는지 본다. **보이면 팀장이 `hwpx-export` 절차대로 직접 변환한다.** 안 보이면 변환을 보류하고 설치 안내를 전한다. 한글 변환까지 끝냈다고 보고하지 않는다

## 9단계 — 최종 보고
1. **산출 파일** — `_workspace/` 아래 00~06 목록과 각 한 줄 설명
2. **사람이 판정할 것** — 빠짐없이, 목록으로
   - 본문의 `[확인 필요: …]` 전수(`grep -n "확인 필요" _workspace/04_검토보고서.md`) — 위치와 함께
   - 본문의 `〔판단 필요: …〕` 전수 — 결론을 긍정·중립·수정의견 중 무엇으로 할지, 부처 의견 기재
   - 검문소 `04c`의 △ 항목
   - 관문② [권고] 가운데 반영하지 않은 것, 잔여 리스크
   - 부처·이해관계자에게 받을 것(조사 장부 끝 목록)
3. **한 줄 경고** — "검문소 통과와 검수 통과는 초안이 맞다는 보증이 아닙니다. 조문과 인용은 원문과 대조하고, 결론은 직접 정하십시오."

## 경량 모드 — 사용자가 "빨리"라고 했을 때
- 관문①은 **그대로 돌린다.** NO-GO면 고치고 재판정한다. 시간을 줄일 때는 사용자와 합의해 쟁점 수를 줄인다
- 쟁점 승인 관문은 **생략하지 않는다**(사람이 서는 자리다)
- 조사는 쟁점 분할 1 + 원장 분할 1, 분할당 도구 호출 20회
- 관문② [필수] 가운데 표기·조문 번호 정정처럼 새 문장이 필요 없는 것은 팀장이 직접 고친다. 새 논증이 필요한 것만 집필가를 부른다
- **조문 대조 검문소는 어떤 모드에서도 생략하지 않는다**

## 막힐 때

| 상황 | 대응 |
|---|---|
| 팀원이 파일을 안 남김 | 응답 내용을 팀장이 지정 경로에 저장하고 진행기록에 적는다 |
| korean-law 도구가 팀원에게 안 보임 | 팀장 도구 목록에 있으면 팀장이 원장 분할을 직접 한다(응답을 한 글자도 고치지 않고 저장). 아무에게도 없으면 원장을 만들 수 없으므로 **검문소 보류** — 국가법령정보 연결을 안내한다(`bill-sources` §1) |
| 네트워크·API 오류 | 인증·한도 오류는 재로그인·한도 회복을 안내하고 멈춘다. 일시적 연결 오류만 같은 요청 1회 재시도 |
| 근거가 전혀 안 나옴 | `[확인 필요]`로 둔 채 진행하고, 부처·이해관계자에게 받을 목록을 키운다. 지어내지 않는다 |
| 검문 2회 불통과 | 보류 — 남은 ✕를 보이고 사용자 지시를 받는다 |

| 에이전트가 목록에 없음 | 플러그인 설치 후 Claude를 다시 시작했는지 확인. 그래도 없으면 `/agents`로 확인 |
