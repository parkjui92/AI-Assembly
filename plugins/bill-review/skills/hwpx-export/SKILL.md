# 한글 문서로 옮기기 — 번호와 대비표를 지키고, 빠진 것이 없음을 숫자로 보인다

검토보고서는 한글 문서로 돈다. 변환에서 **번호가 바뀌거나 대비표 한 행이 빠지거나 `-` 줄이 깨지면** 내용이 맞아도 쓸 수 없다.
그래서 변환가는 문장을 고치지 않고, 대신 **변환 전후를 숫자로 맞춰 보인다.**

> **의존성** — kordoc(제3자 오픈소스, `github.com/chrisryugj/kordoc`). 설치: `claude mcp add kordoc -- npx -y kordoc@latest mcp`
> (Node.js 20 이상). 없으면 변환을 보류하고 마크다운 원고를 최종본으로 둔다.

## 1. 시작 조건
- `05_검수판정.md`가 "통과"이거나, [필수] 뒤 재판정 통과가 붙어 있어야 한다. 아니면 시작하지 않고 팀장에게 알린다
- `04c_조문대조.md`의 판정이 "통과"인지 본다. 불통과면 시작하지 않는다
- `00_input/`에 실물 검토보고서 `.hwpx`가 있으면 3-B. `.hwp`만 있으면 한글에서 `.hwpx`로 저장해 달라고 안내한다

## 2. 전처리 → `_workspace/06a_변환용.md`
원고를 복사해 아래만 손본다. **문장·조문·`[확인 필요]`·`〔판단 필요〕` 표시는 그대로 둔다** — 사람이 판정할 자리다.
- 제목 단계가 `review-writing` §12 표기 약속과 맞는지 확인한다. 어긋나면 고치지 말고 팀장에게 알린다
- 줄 맨 앞의 마크다운 목록 기호(`* `·`- ` 뒤 공백으로 시작하는 목록)가 `□`·`○` 대신 쓰였으면 위치를 보고한다(임의로 바꾸지 않는다). `- `로 시작하는 3단 부호는 원고 그대로 둔다
- 대비표 칸 안의 `<br>`은 그대로 둔다(셀 안 줄바꿈)
- 각주 `[^n]`이 변환에서 살지 않으면 본문 끝 「주」 절로 모은다 — 바꾼 사실을 보고에 적는다
- 원고 끝의 작업 메모(있으면)만 뺀다

## 3. 변환

### 3-A. 기본 — 범용 모드
```
mcp__kordoc__generate_document(
  markdown = (06a_변환용.md 전문),
  output_path = (작업 폴더 절대경로)/_workspace/06_검토보고서.hwpx,
  font = "myeongjo"
)            ← preset 은 지정하지 않는다
```
`개조식`·`보고서` 같은 공문서 프리셋은 장 번호와 부호를 자기 체계(□·○)로 다시 매긴다. 범용 모드는 원고의 `Ⅰ.`·`1.`·`가.`·`□`·`○`를 글자 그대로 둔다.

### 3-B. 실물 검토보고서가 있을 때 — 그 표 서식을 따른다
1. `mcp__kordoc__extract_profile(hwpx_path=실물, output_path=_workspace/06b_서식프로필.json)`
2. 3-A 호출에 `profile_path`를 더한다 (행·열 수와 첫 칸 글자가 같은 표에만 적용된다. 적용 안 된 표는 보고에 적는다)
3. 본문 글꼴·크기·머리말·표지는 렌더를 실물과 나란히 보고 `body_pt`·`line_spacing`으로 맞춘다. 끝내 다른 것은 **한글에서 손으로 맞추게** 안내한다

### 3-C. 소형 시험 먼저
Ⅲ장의 첫 쟁점 하나만 변환해 재파싱하고, 번호 부호와 대비표의 `-` 줄·`(현행과 같음)`·`<신 설>`이 살아 있는지 확인한 뒤 전체를 변환한다.

## 4. 검증 — 숫자로 1:1
`mcp__kordoc__parse_document`로 `06`을 다시 읽어 원고(`06a`)와 맞춘다.

| 항목 | 맞추는 법 |
|---|---|
| 표 개수 | 원고 표 수 = 문서 표 수 |
| 대비표 행 수 | 대비표마다 원고 행 수 = 문서 행 수. 의심되면 `parse_table`로 그 표만 |
| 번호 부호 | `Ⅰ.`·`Ⅱ.`·`Ⅲ.` · `1.` 쟁점 · `가.` · `□` · `○` 개수가 같다 |
| 대비표 표기 | `(현행과 같음)` · `(생 략)` · `<신 설>` · `<삭 제>` 개수가 같다 |
| 표시 | `[확인 필요` 개수 = · `〔판단 필요` 개수 = |
| 본문 | 공백을 접어 비교한다 |

- **개수가 어긋난 채로 "이상 없음"이라고 쓰지 않는다.** 어긋나면 고쳐 다시 만들고(최대 2회), 그래도 어긋나면 어긋난 그대로 보고한다
- **구조 검증** — `npx -y kordoc@latest validate _workspace/06_검토보고서.hwpx`
- **렌더로 눈으로 본다** — `mcp__kordoc__render_document`. 실패하면 `npx -y kordoc@latest render _workspace/06_검토보고서.hwpx -o _workspace/06c_미리보기.svg`. 둘 다 안 되면 "렌더 확인 못 함 — 한글에서 열어 확인 필요"
- 팀장은 변환가 보고의 개수를 한 번 다시 센다(자기보고를 믿지 않는다)

## 5. 보고 (변환가 응답)
```
06_검토보고서.hwpx 생성 — 범용 모드 · 표 서식: 기본 / 실물 공여(파일명, 적용 표 n/n)
검증: 표 n/n · 대비표 행 일치 n/n · 번호 부호 원고 n = 문서 n · 대비표 표기 n = n
      [확인 필요] n = n · 〔판단 필요〕 n = n
렌더: 확인함 / 확인 못 함(사유)
형식 조정: (없음 / 무엇을 왜)
남은 손작업: (한글에서 맞출 것 — 표지·머리말·쪽번호 등)
```

## 6. 막힐 때
| 상황 | 대응 |
|---|---|
| kordoc 도구가 안 보임 | 변환 보류. 설치 명령을 팀장에게 돌려준다. 원고는 `04_검토보고서.md`가 최종본 |
| MCP 호출이 막힘 | **생성은 MCP로만 한다.** CLI `kordoc generate`는 범용 모드가 없어 번호를 다시 매긴다. CLI는 읽기·검증·렌더에만 |
| 검증이 두 번 어긋남 | 상위 모델로 다시 불러 달라고 팀장에게 요청 |
| 대비표 칸이 좁아 `-` 줄이 여러 줄로 갈림 | 한글의 정상 조판이다(글자는 그대로). 렌더에서 칸 폭만 확인한다 |

## 하지 않는 것
- 문장·조문을 고치거나 줄이기, 표시를 지우기
- 통과 전 원고 변환 · 실물 검토보고서 원본 덮어쓰기
